Detected Bottlenecks

Socket.IO EIO4 — Poll Required After Connect

EIO4 protocol requires a GET poll after sending "40" connect packet to receive server namespace confirmation before emitting any events. Missing this poll causes "Session ID unknown" errors.

Socket.IO Session Expiry — 25s pingInterval

Sessions expire in 25 seconds without a ping. Script sends ping packet "2" every 10 seconds during bid loop to prevent session expiry errors.

Bidder Reserved Status Blocks Assignment

Server marks bidders as reserved when assigned to auctions. Setup closes all existing auctions (Step 2.5) to unreserve bidders before creating new test auctions.

PostgreSQL Connection Pool Pressure

Each bid triggers a DB write. Knex default pool of 10 will queue under 10k concurrent load. Increase to pool.max=100 with PgBouncer.

Auction Timer Broadcast at 10k Scale

Server emits auction:timer every second to all room members. At 10k VUs this will heavily stress the event loop. Monitor lag closely.

Recommendations
1

Increase PostgreSQL pool — pool.max=100 + PgBouncer

Set Knex pool.max=100 and add PgBouncer to handle concurrent bid writes at 10k scale.

2

Run PM2 in cluster mode with Redis Socket.IO adapter

pm2 start app.js -i max. Add @socket.io/redis-adapter for cross-instance room support.

3

Cache GET /api/auction/auctions with Redis 5s TTL

Every VU calls this — a 5s Redis cache reduces DB reads by 95% at peak.

4

Throttle auction:timer broadcast to every 3s

Reduces event loop pressure by 66% for rooms with 1000+ concurrent bidders.

5

Add direct bidder unreserve API endpoint

Currently only auction close/delete unreserves bidders. A direct endpoint simplifies management.
